# 页面类型与内容判断

本文件只判断“页面承担什么用户任务、内容是否把任务讲透”。技术证据按 [`framework-adapters.md`](framework-adapters.md)；严重度只按 [`diagnostic-rubric.md`](diagnostic-rubric.md)。

## 通用判断

### 一页一主意图

每个目标查询应映射到一个最合适的页面，而不是把所有关键词套到所有页面。审计时记录：

- 用户要完成的任务；
- 页面承诺的结果；
- 支撑结果所需的解释、步骤、示例和限制；
- 与相邻页面的边界；
- 关键词映射来自用户、routes file、页面内容还是推断。

意图不明时标 `Unknown`。用户只给出词表时，将未映射词列为机会，不据此判断每页缺词。

### 信息增益，不看固定字数

内容是否足够取决于任务，不取决于字符数。短页面可以完整解决简单任务；长页面也可能只重复营销话术。检查：

- 是否直接回答用户的主要问题；
- 是否给出可执行步骤、输入/输出、示例、限制和异常情况；
- 是否提供站点自身能验证的经验、数据、工具能力或独特整理；
- 是否存在大段重复、占位、批量改词或无来源承诺；
- 页面模块是否服务任务，而不是为了凑模板。

Google 明确表示不存在最佳关键词密度。不得使用 `3%–5%`、`8%` 或其他密度阈值；只检查措辞是否自然、实体和主题是否足以让用户理解页面。[Google Search Central](https://developers.google.com/search/help/office-hours/2023/january?hl=en)

### 主标题清晰

判断用户能否立刻识别页面主题。多个 H1 不自动构成问题；只有多个同等显著标题让主标题不清，或页面根本没有明确主标题时才报告。[Google title links 指南](https://developers.google.com/search/docs/appearance/title-link)

### 真实用户语言

- YMYL 不是禁词。只有公开页面对健康、财务、法律、安全或重大福祉给出无依据建议、保证、诊断或收益承诺时，才是风险线索。
- 法律免责声明、隐私说明和服务条款应按其页面任务判断，不能因出现风险词直接定性。
- 内部 PRD、注释、prompt、模型过程、草稿和测试 fixture 不属于页面文案。
- 只有已映射到公开页面的用户可见内部说明或占位内容，才能升级为页面问题。

## 页面类型

### 工具 / SaaS 落地页

围绕“完成任务”检查：

- 工具入口与价值承诺是否一致；
- 输入、处理步骤、输出和下载/后续动作是否清楚；
- 能力、限制、隐私/安全边界是否具体；
- 是否有真实示例、常见失败情况和 FAQ；
- 是否链接到相关工具、格式或任务页面；
- CTA 是否帮助继续任务，而不是重复口号。

### 游戏页

游戏本体不是全部内容。检查：

- 玩法、控制方式、目标、规则和常见问题；
- 游戏版本、来源或授权边界能否说明；
- 页面是否只是 iframe/按钮/封面薄壳；
- 相关游戏和攻略是否确实相关，而不是随机推荐；
- 文案是否为该游戏原创整理，而非批量换名。

### 博客 / 指南

- 开头是否快速回答查询；
- 论点是否由步骤、例子、数据或来源支撑；
- 作者/编辑责任、更新时间和引用是否适合主题风险；
- 章节是否覆盖用户决策过程，而非机械 FAQ；
- 是否连接到支柱页、相关指南或下一步工具；
- 更新是否增加事实价值，而非只改日期。

### 目录 / 分类 / 图片集合

- 分类标准是否清楚，条目是否真实属于该集合；
- 分类说明是否帮助选择，而非重复条目标题；
- 每个条目是否有可辨识预览和去向；
- 筛选、分页、子分类是否解决不同任务；
- 图片说明和周边文本是否提供可读信息；
- 是否存在大量空分类、近重复分类或无独立价值的组合页。

### 电商 / 产品

- 分类页是否帮助比较和筛选，而非只有商品网格；
- 产品页是否提供规格、适用场景、限制、库存/价格和真实证据；
- 评分、评论、案例和优惠是否可验证；
- 缺货、停产和替代品信息是否帮助用户继续决策；
- 相近变体是否有清楚差异，而非批量重复描述。

### 本地服务 / 专业服务

- 服务范围、地点、对象、过程、交付和费用边界是否具体；
- 资质、案例、评价和联系方式是否真实可验证；
- 不同地区页是否有真实地区差异，而非只替换地名；
- 高风险主题是否区分一般信息与个体建议。

### 信任 / 法律页面

- About 说明主体、职责和维护方式；
- Contact 提供可用联系路径；
- Privacy/Terms 反映实际数据流和服务边界；
- 免责声明不替代正文证据，也不能被当作 YMYL 承诺；
- 这些页面的任务是建立透明度，不用强行承载商业关键词。

## 内容结论的证据要求

内容缺口必须写成“目标任务 + 当前页面证据 + 缺失信息 + 用户影响”，不能只写“内容薄”“关键词少”或“缺 FAQ”。如果页面尚未完成 URL 覆盖，结论只能是 `Candidate/Unknown`。
