# 中文 SEO 方法论整理

本文件是对中文 SEO 实践经验的结构化整理，供 Codex 做代码审计时复用。不要机械套模板；每次要结合网站类型、关键词和代码实现判断。优先级和「什么算排名信号」对照 `zyppy-2026-ranking-factors.md`：专家共识 ≠ Google 官方权重；本 skill 不替代 GSC/Ahrefs。

## 1. 一个关键词要有一个真正说透的页面

如果想获取某个关键词的自然搜索流量，就要围绕这个关键词做一个对应页面。页面不只是放一个标题，而是要满足用户想要的结果类型/任务（Search Intent Match），并把用户围绕这个任务会关心的内容讲清楚。

典型工具落地页模块：

1. 工具名称、核心卖点、工具入口；
2. How it works：具体任务步骤；
3. Features：功能点和差异点；
4. 更细的使用流程或应用场景；
5. FAQ；
6. 用户证言/信任信号；
7. 相关功能/相关关键词链接列表；
8. 再次 CTA 或工具入口。

诊断代码时，不能只看页面是否漂亮，要看源 HTML 中有没有这些可读内容。

## 2. 关键词密度不是诊断目标，只抓堆砌

不要把 3%–5%（或 8% 上限）当成优化区间。密度不是排名旋钮。

诊断时只做两件事：

- **覆盖**：目标意图/关键词是否在 title、H1、可见正文中自然出现；没出现就谈映射和意图，不谈「密度偏低」。
- **堆砌**：只有密度异常高、或同一短语机械重复时，才标关键词堆砌。

更好的做法是：

- 先匹配 Search Intent（用户要的结果类型/任务），再写 title/H1/首段；
- 用同义词、二级词、三级词、场景词、问题词围绕主词解释；
- 很多页都已覆盖同一意图时，补信息增益（一手数据、原创方法、独特示例），而不是重复主词。

## 3. HTML 语义结构必须清晰

每个核心页面都需要：

- title（先检查相关性，再检查是否利于点击）；
- meta description（CTR 杠杆，**不是已被证明的排名因子**；缺了按 P2/P3，不按 P1）；
- canonical；
- 一个 H1；
- 多个有层级的 H2/H3；
- 正文 p / list / table；
- img + alt；
- 必要时 JSON-LD schema。

把 title 拆开看：相关性 = 是否表达本页任务；CTR = 是否在 SERP 上吸引点击。H1 更偏用户进入页面后的主题确认。title 与 H1 可以相近，但不能混乱或缺失。

## 4. “分门别类罗列”是目录站/工具站/内容站首页的关键策略

首页或支柱页要把主词、二级词、三级词分门别类展示出来。

以 coloring pages 为例：

- H1：coloring pages
- H2：dog coloring pages
  - H3：cute dog coloring pages
  - H3：little dog coloring pages
- H2：cat coloring pages
  - H3：cute cat coloring pages
  - H3：little cat coloring pages
- H2：flower coloring pages
  - H3：red flower coloring pages
  - H3：yellow flower coloring pages

审计时要判断站点是否把关键词层级映射到了页面层级和标题层级，而不是只有孤立页面。

## 5. 内链是站点可端到端控制的杠杆

外链质量（信任域名 + 主题相关 + 来源页有真实访问）通常无法从代码证明，必须标 Unknown。内链可以、也应该在代码审计里给具体建议。

站内链接应符合层级：

- 首页链接到二级关键词页；
- 二级关键词页链接到三级关键词页；
- 三级关键词页用明确锚文本链接回二级关键词页；
- 二级关键词页链接回首页；
- 所有核心页面自然链接回首页或主支柱页；
- 页面中提到某个关键词时，尽量链接到站内对应页面。

诊断输出要给具体内链建议：来源页、锚文本、目标页、为什么要加。

## 6. 新站优先后端渲染或静态生成（table stakes）

技术 SEO 是桌面筹码，不是增长解锁：坏的渲染/抓取/canonical 会让你输掉；修好也不会把平庸内容抬上去。不要把 CWV 写成主优化目标。

核心 SEO 内容需要直接体现在 HTML 源代码里。不能只靠前端 JS 渲染后才出现。

审计时要做两层检查：

1. 源码或组件里有没有 SEO 内容；
2. 构建后/查看源代码时，title、description、H1、正文、canonical、内链是否真的出现在 HTML 中。

对于纯 SPA 或整页 Client Component，要标为风险，并建议 SSR/SSG/prerender。

## 7. URL 唯一和 canonical 非常重要

一个页面可能可以通过多个 URL 访问，例如：

- www 与裸域名；
- http 与 https；
- trailing slash 与 non-trailing slash；
- 参数 URL；
- 别名 URL；
- 多语言/地区 URL。

每个页面要通过 canonical 告诉搜索引擎规范 URL。canonical 应该：

- 使用绝对 URL；
- 使用正确域名；
- 使用 HTTPS；
- 每页只有一个；
- sitemap 和内链尽量使用 canonical URL。

## 8. 上线后的 SEO 迭代节奏

这部分通常不能只靠代码判断，但报告可以提醒用户。优先看意图是否匹配、任务是否完成、GSC 点击质量；不要把「外链数量」或密度当主路径。

1. 建站初期先筛词库，按搜索意图（要的结果类型/任务）归类后布局到页面；
2. 上线后提交 Google Search Console，先看收录是否稳定，再看点击质量（展示、点击、CTR、查询是否与页面任务匹配）；不要用 bounce rate 当满意度；
3. 外链优先来自受信任域名、主题相关、且该来源页有真实访问的链接；不要追求链接数量。垃圾链是强负向。精确匹配锚文本利弊取决于它在锚文本画像中的占比；
4. 如果用户能完成任务、有回访或品牌查询，再增加有信息增益的页面，而不是批量薄页；
5. 用户若提供 Ahrefs/Semrush，看主题覆盖和链接质量，不要编造词库/外链数字；
6. 关注前 20 名查询：先确认意图是否匹配，再分别改 title 相关性或 title/description CTR 文案；
7. 优化后不要频繁改动，观察 1–2 周；
8. 有页面进入可见位置后，总结「意图 + 原创信息 + 内链」共性，再复制到下一批页面。

技术健康是持续维护的 table stakes，不是这一阶段的增长手段。

## 9. 代码审计不要发明的信号

没有 GSC / Ahrefs / 用户研究时，下面全部标 Unknown：行为与 CTR、任务完成、品牌词搜索量、线上口碑强度、外链质量、主题权威分数。专家调研里这些很重要，但本 skill 不能假装从仓库里算出来。
